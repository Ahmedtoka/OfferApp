# Security review: Le Voile BOGO app (design §7)

- **Date:** 2026-10-30
- **Scope:** `web/` (Laravel 12, PHP 8.2) and `extensions/bogo-discount/` (JS Discount Function → Wasm)
- **Method:** I tried to run the `security-review` skill, but it failed to load because the repo has no `origin` remote (`git log origin/HEAD...` → "unknown revision"). I followed its method by hand instead: a read-only pass over every route, middleware, controller, service, view and Function source file, then a throwaway probe test to confirm each suspicion before calling it a finding. Then each finding got a failing test, a fix and its own commit.
- **Design decisions taken as given (evaluated, not re-argued):** App Bridge session token (HS256) plus token exchange with no OAuth redirect; page load verified by the admin query `hmac` or `id_token`; bearer-only `/api/*`; webhook HMAC on `X-Shopify-Hmac-Sha256`; Admin GraphQL server-side only; shop allow-list in config.

## Minor / hardening (not fixed; recorded for the owner)

1. **Webhook headers are not covered by the HMAC.** `X-Shopify-Topic` and `X-Shopify-Shop-Domain` (`WebhookController.php:16-17`) are trusted after a body-only HMAC. Someone who captured one genuine signed webhook (that takes TLS interception or log access) could replay its body with `app/uninstalled` and another shop's domain, and so wipe that shop's token. Hardening: for `app/uninstalled`, require the body's `myshopify_domain` to equal the header, and de-duplicate on `X-Shopify-Webhook-Id`.
2. **The admin page-load `hmac` has no `timestamp` freshness check** (`VerifyAdminQueryHmac.php`). Replaying a captured admin URL renders only public values (the API key and constants), and every data call still needs a fresh session token, so the impact is negligible. Optional hardening: reject a `timestamp` older than about 5 minutes.
3. **`.env.example` has `APP_ENV=local` and `LOG_LEVEL=debug`.** Production `.env` should use `APP_ENV=production` and `LOG_LEVEL=info` or higher. Neither value exposes secrets (`APP_DEBUG=false`).
4. **The Function's work grows with the square of unit count for odd counts** (`bogo.js` `computeOffer`: n candidates × O(n) build). A cart with hundreds of units could exceed Shopify's Function instruction limit. That fails closed (no discount), so this is availability and correctness, not security; it belongs to the Function owner.
5. **No `jti` replay cache for session tokens.** Shopify tokens live 60s and the app is single-merchant, so this is acceptable as designed.
