# Security review: Pairly public app, before App Store submission

- **Date:** 2026-10-31
- **Branch:** `feat/pairly-public-app` against `main`
- **Scope:** `web/` (Laravel 12), `extensions/bogo-discount/`, `extensions/pairly-theme/`, tracked docs, full git history
- **Spec:** `docs/superpowers/specs/2026-10-31-bogo-public-app-design.md`. Earlier review: `docs/security/2026-10-30-review.md`.
- **Method:** read every route, middleware, controller, form request, Shopify service, Blade view, Liquid file and `pairly.js`. Searched `app.js` and the site scripts for DOM sinks and read the matches. Scanned history with regexes. Reproduced each suspicion with a test before calling it a finding.
- **Limits:** nothing was deployed, pushed, installed or sent to Shopify, and `web/.env` was not read. Behaviour that depends on real Shopify payloads is listed under "Not verified". `gitleaks` and `trufflehog` are not installed, so the history scan is regex-based. The screenshots in `docs/qa/` were not reviewed for sensitive content.
- **Concurrent work:** another agent committed to this branch during the review (`89a8878`, `bf892f9`). Those commits were not reviewed line by line, but the final test run includes them.

## Open items that need the owner

- **O1 (Medium, billing): a fresh 14-day trial on every new subscription.** `Billing.php:84` always sends `trialDays: 14`. A merchant can uninstall, reinstall and subscribe again every 14 days and never pay. Fixing it needs remembered state, and `shop/redact` deletes the shop row 48 hours after uninstall, as the spec requires. Decide one of:
  - (a) keep a salted hash of the shop domain plus the trial date after redact, and state that in the privacy policy;
  - (b) read `currentAppInstallation.allSubscriptions`, which stops repeats within one installation, though whether it survives a reinstall must be checked on a dev store;
  - (c) accept the loss.
- **O2 (Medium, billing): nothing re-checks an offer that is already on.** The gate runs only when saving, and the off switch only on the webhook. The offer stays on free if a partner dev store moves to a paid plan (no billing webhook fires), or if Shopify gives up delivering `app_subscriptions/update`. Fixing it needs a scheduled job on the server, and possibly a `shop/update` subscription in `shopify.app.bogo.toml`, which this review was told not to edit. Decide whether to build it before submission.
- **O3 (Low): change the dev storefront password** in Online Store → Preferences. The old value remains in history on `main` and on the public remote (first in `6988c38`). Changing it is enough, so a history rewrite is not recommended. `docs/` also names the dev store and a `shopifypreview.com` preview link.
- **O4: re-accept `npm audit`.** The acceptance recorded in `docs/deploy.md:319` covers the 25 high findings. There is one new moderate: `minimatch` (GHSA-g3hv-75wg-m249) through `@shopify/shopify_function` → `graphql-config`, also build-time. `extensions/bogo-discount/dist/function.js` has 0 matches for `lodash|graphql-tools|mergeDeep|minimatch`. The only offered fix is a breaking downgrade to `@shopify/shopify_function@1.0.5`.
- **O5 (deployment): check these in the production `.env`; none can be enforced from the repo.**
  - `APP_ENV=production`. Any other value makes charges test charges and makes them count (`Billing.php:46,83`), so the app is free. `.env.example` ships `local`.
  - `SHOPIFY_BILLING_REQUIRED` unset or `true`. An empty or mistyped value turns the gate off (`config/shopify.php:36`).
  - `APP_DEBUG=false`, a `LOG_LEVEL` of `warning` or higher, and `LOG_STACK=daily`. Each bad-HMAC webhook writes a log line, and `single` grows without limit.
  - Rate-limit anonymous routes at the server: the marketing pages and `/webhooks` have no Laravel limit.
- **O6 (hardening, optional).**
  - Add `script-src`, `X-Content-Type-Options` and `Referrer-Policy` to the marketing pages. This needs a browser check against the 3D scene, and App Bridge limits what the admin page can adopt.
  - De-duplicate webhooks on `X-Shopify-Webhook-Id`. A replayed genuine uninstall after a reinstall still wipes the token until the next admin visit.
  - Add a `timestamp` check on the admin `hmac`. That load renders only public values.

## Not verified

- **Real webhook payloads.** F4 assumes Shopify's `app/uninstalled` body always carries `myshopify_domain`. **Check this on the dev store before submission**, because an uninstall whose body lacks it would now leave the token in place. F5 is defensive: the real status casing was not observed.
- **Browser behaviour of F1.** Removing cookies should change nothing, since no route used them, but it was tested only through the HTTP test client. Open the embedded app in Chrome incognito once.
- **Production settings:** real database cache behaviour under load, Cloudways web root, HTTPS.
- **Screenshots in `docs/qa/`** were not reviewed for sensitive content.
