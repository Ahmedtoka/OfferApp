## Blockers before live

1. **B1: Production hosting does not exist.** `offer.arenahere.com` does not resolve (NXDOMAIN). Complete `deploy.md` §2–§3 (DNS, SSL, webroot `web/public`, production `.env` with `APP_ENV=production`, `DB_CONNECTION=mysql`, `LOG_LEVEL=warning`, `migrate --force`, config cache). Then `curl -I https://offer.arenahere.com/` must return a Laravel response.
2. **B2: Deploy and smoke-test a released version of HEAD.** The active app version predates every commit. If it were installed today, the live store would get spike-era config and Function code. Run `shopify app deploy` from a clean HEAD. Confirm with `shopify app versions list` that the new version is active, and that the install screen will request exactly the 3 scopes. Then, with `shopify app dev` **stopped**, rerun a short smoke test on `levoilest` against the released build and the Cloudways host: page loads embedded, Save, `abc` = 1830, offer OFF = no discount, coupon rejected, analytics loads.
3. **B3: Analytics can count discounts the app did not create** (spec anti-goal: "numbers that disagree with Shopify's own order totals"). This was introduced by the English strings. `OfferAnalytics::classify()` (`OfferAnalytics.php:137-158`) matches on title only and also accepts `ManualDiscountApplication` (fetched at `OrdersFetcher.php:35`). Any staff manual discount titled "Gift", or any automatic discount titled "N% off", is therefore counted as the offer. The 60-day window includes the live store's pre-install orders. The parallel delta review (`docs/reviews/2026-10-30-delta-review.md`, I1) found the same issue independently. Fix: accept only `AutomaticDiscountApplication`, bound the parsed percent to 1–99, and add tests (manual "Gift" ignored, "150% off" ignored). The minimum alternative: before install, verify there is no Gift / "N% off" / "Buy One Get One" titled discount or manual-discount usage on the live store in the last 60 days, and record the owner's acceptance.

## Open risks the owner accepts (or must explicitly decide)

- **R1 npm audit:** 25 high in build-time codegen deps, absent from the shipped bundle (verified). The owner's written acceptance is still to be recorded.
- **R2 Multi-currency:** prices are computed in the presentment currency; 2-decimal rounding is wrong for 3-decimal currencies; untested. Confirm the live Markets currencies. If only EGP, this risk does not apply.
- **R3 POS / draft orders:** out of scope. Unverified whether the offer applies there.
- **R4 Flutter app:** in-app cart and checkout not tested. Do one real-device check right after switching the offer on.
- **R5 Shared app for dev and live:** `automatically_update_urls_on_dev = true` (`shopify.app.toml:11`), and `deploy.md` §6 still says to keep using `shopify app dev` on the dev store. Confirm that a dev preview cannot change the live app's URLs/config, or stop running `app dev` on this app after go-live (final review M10).
- **R6 Other automatic discounts:** §5 deactivates codes only. An active non-combinable automatic discount on the live store can displace the offer. That cannot cause stacking, but it can mean "no BOGO". Add a §5 step (M12).
- **R7 The "never raise a price" discount-0 branch** has fixture coverage only (`markdown_single_650_alone.json`). No live screenshot.
- **R8 Analytics freshness:** results are cached for 10 minutes, so ranges can disagree briefly (seen in QA). The page says "active in Shopify" while the offer is OFF (M1). Analytics was never compared with Shopify's own discount report.
- **R9 Remaining open minors** from the final review (M2–M17, e.g. webhook headers not HMAC-covered, no `nbf` leeway, concurrent-save double-create). None blocks launch.

## Verdict

**NEEDS WORK.** Not certified for `levoilestores.myshopify.com`. The code, tests, build, config, default-off, kill switches and checkout behaviour pass with evidence. Re-run this gate after B1–B3 are closed. Expect one short cycle: hosting, deploy and smoke test, plus a small analytics fix with tests.
